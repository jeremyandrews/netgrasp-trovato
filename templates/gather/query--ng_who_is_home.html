{# Who is home. /who-is-home A device gather read as a people page. The rows are online devices that belong to somebody — with no grouping in QueryDefinition, a person with three devices arrives as three rows (G-NO-GATHER-AGGREGATION), which is why the gather sorts by owner: the repetition at least arrives adjacent. `unique` then `filter` finishes the job in the template: one card per distinct owner, then that owner's devices picked back out of `rows`. Both key on `owner_item_id` — the physical column name, because these are records — and the gather's `owner_id is_not_null` filter is what guarantees every row has one to key on. Keyed on the id and NOT on the name, deliberately, even though the name is what the card shows: two people may share a name, and merging them into one card would be a wrong answer to the only question this page asks. =========================================================================== Why not `group_by`, which is the obvious filter for this =========================================================================== Because it silently reorders the cards. `group_by` returns a map, and Tera builds that on `serde_json::Map` with `preserve_order` off, so it is a BTreeMap and iterating it yields the cards in UUID order — which for UUIDv7 means the order the people were created in, whatever the gather's ORDER BY said. The sort by `owner_name` in 006_netgrasp_owner_names.sql had no effect at all while this used `group_by`, and nothing pointed that out: the page rendered, in a plausible-looking order that simply was not the one asked for. `unique` preserves input order and hands back the whole first row of each group, so the SQL sort survives and the name is on the row that heads the card. The name arrives as `owner_name`, from the view the `ng_device_state` record type is declared over. The card used to show a uuid, because a gather reads one record type and ng_people is a different table. #} {% extends "gather/netgrasp/page.html" %} {% block summary %} {% set ng_people = rows | unique(attribute="owner_item_id") %}
