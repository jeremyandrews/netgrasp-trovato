{# The per-row actions menu, shared by the device table, the event table and the people list. One partial for all three, for the reason device-table.html gives about itself: three copies of a menu is a menu that stops agreeing with itself the first time an entry is added to one of them. =========================================================================== Why every entry is a LINK and not a form =========================================================================== A write has to carry the kernel's `_token`, and **a gather content template cannot render one.** The gather route renders this template in a context of its own — `query`, `rows`, `total`, `page`, `per_page`, `total_pages`, `has_next`, `has_prev`, `base_path`, `exposed_filters`, `filter_values`, `pager`, and nothing else (`crates/kernel/src/routes/gather.rs`, `render_gather_with_theme`). The site context that carries `csrf_token` is built *afterwards*, for the page wrapper around this content (`routes/helpers.rs`, `inject_site_context`). The two never meet. So a `
` written here would post without a token and the kernel would refuse it with 403 before the plugin was dispatched at all — not a bug to be found later, a feature that could never have worked. What does work, and is what every entry below does: link to a page the PLUGIN serves. `tap_api` is handed a freshly minted token in `ApiRequest::csrf_token`, so the plugin renders the single-field form with a valid token in it and the POST goes from there. That is the `trovato_contact` pattern, and it is the only no-JavaScript write path a plugin has. `FRICTION.md`, `G-GATHER-TEMPLATE-NO-CSRF`. It is also what makes "Assign owner" a select of people at all: a gather reads ONE record type, so the people list is not in this context either. The page the link opens can read it; this template cannot. =========================================================================== What the caller sets before including =========================================================================== - `ng_row_kind` — "device" or "person". Decides which entries appear. - `ng_row_ref` — how the plugin is to find the thing: a MAC or an `ng_devices.id` for a device, a person's Item uuid for a person. The device forms parse either, the same way `netgrasp_core::assist::parse_device_ref` does, which is what lets an event row — which carries `device_id` and no MAC — offer the same device actions as a device row. - `ng_row_label` — what to call it in the menu's accessible name. - `ng_row_item` — the Trovato Item uuid, or empty. Empty is normal: a device has no Item until the cron sync mints one, and a row the daemon has never marked dirty may never have had one (DESIGN.md Decision 9). - `ng_row_flags` — whether this row carries the device's user-owned flags. A device row does; an event row does not. - `ng_row_hidden` / `ng_row_notify` — those flags, read only when `ng_row_flags` says they mean anything. Devices only. - `ng_row_id` — a value unique on the page, for the `id` attributes. `base_path` is the listing to come back to and comes from the gather context, not from the caller. #} {# Each filtered value is bound on its own line and interpolated at the point of use.
