{# The device table, shared by all four device gathers: ng_device_list, ng_device_online, ng_device_by_type and ng_device_by_owner. One table, four pages. The four differ only in which rows the gather selects, so they have no business differing in how a row is drawn — and a column added to one copy of four is a column missing from three. Rows are `ng_device_state` records: flat objects keyed by the physical column names of ng_devices. See gather/netgrasp/page.html for what happens when a template forgets that. #}
{% for row in rows %} {# The daemon's naming ladder: an admin's label wins, then what the daemon resolved, then the raw hostname, then the MAC — which is never null. Written as an if-chain for two reasons. These columns arrive as JSON null, and the `default` filter only substitutes for an *undefined* value, so it would not fire. And Tera's `or` is a boolean operator, not a coalesce: `a or b` yields `true`, not `a` — a chain of them renders the literal word "true" in the column. Linked only once the cron sync has minted the device's Item. Until then trovato_item_id is null, and the record id is a bigint the uuid-keyed item route cannot open. The anchor is opened and closed around the name rather than binding the name to a variable first: `{% set %}` inside an `{% if %}` is not reliably visible after the `{% endif %}`, and an undefined variable does not render as blank here — it aborts the whole template. #} {# The type facet is a route, not an exposed filter (see 002_netgrasp_gathers.sql), so this link is how a reader gets to /devices/type without typing a query string. #} {# The owner's NAME, since 006_netgrasp_owner_names.sql: the record type is declared over a view that left-joins ng_people, so `owner_name` arrives on the row. It used to be a uuid chip, because a gather reads one record type and there was no ng_people row to take a name from. The chip is still the fallback, for the case the view cannot resolve: a device naming an owner whose mirror row is gone. Showing the id then is better than an empty cell — it is the only handle on a dangling reference anybody has. The chip shows the *last* group of the uuid, not the first. These ids are UUIDv7: the leading bytes are a timestamp, so two people created in the same millisecond — which is what happens when they are seeded together — share the first eight characters exactly and the chip distinguishes nothing. The final group is the random one. The full id is in the title either way. #} {# The epoch twin, not `last_seen_at`. The timestamptz reaches a gather as an ISO 8601 string through row_to_json and reaches the plugin's db host as null; the twin is the same integer on both paths, and `date` takes it directly. `date` renders UTC. `data-ng-epoch` is what the script in page.html rewrites into the viewer's own timezone. #} {% endfor %}
